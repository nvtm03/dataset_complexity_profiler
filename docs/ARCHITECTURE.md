# Архитектура и устройство пакета

Задача узкая: на размеченном датасете — сыром тексте или уже вычисленных эмбеддингах — определить, до какой размерности можно сжать векторы через PCA без существенной потери качества downstream-модели. Это не классификатор текстов и не AutoML общего назначения.

### Три семейства задач

1. `single` — один текст, задача классификации;
2. `pair` — два текста, задача классификации пары (NLI, парафраз и т.д.);
3. `sts` — два текста, непрерывная оценка семантической близости.

Мета-модель обучалась исключительно на плотных текстовых эмбеддингах языковых моделей (`SentenceTransformer`). Для разнородных табличных датасетов (вроде классических бенчмарков OpenML) инструмент не тестировался и не предназначен.

Код экспериментов и пайплайны обучения вынесены в директорию `research/`. Метрики качества модели зафиксированы в [META_MODEL_METRICS.md](META_MODEL_METRICS.md), теоретическая база — в [RELATED_WORK.md](RELATED_WORK.md).

## Что вызывает пользователь

Точка входа — класс `DatasetProfiler`. CLI (`dcp analyze`) служит консольной обёрткой: загружает CSV или сплит из Hugging Face и вызывает тот же профилировщик.

Публичный API принимает два типа данных:

- сырой текст: метод `analyze_text_dataset(texts, labels)` (требует зависимость `[text]`);
- готовая матрица эмбеддингов: метод `analyze_and_adapt(X, y)` (работает в минимальной установке, не требует `torch` и `transformers`).

Метода `analyze_embeddings` в библиотеке нет.

```text
сырой текст                              готовая матрица X
     │                                           │
n < 30 или 1 класс → ValueError                  │
(до загрузки весов MiniLM)                       │
     │                                           │
MiniLM батчами, вся матрица в RAM                │
сразу float64                                    │
     │                                           │
     └───────────────────┬───────────────────────┘
                         ▼
                   prepare_data
         (удаление пустых меток, NaN/Inf → 0)
                         │
                   n < 30 или 1 класс
                  на очищенной матрице
                         │
                   Бейзлайн-гейт
               нет сигнала → ValueError
                         │
        ┌────────────────┴────────────────┐
        ▼                                 ▼
   predictive                         empirical
   5 признаков → RF                   сетка PCA на train-фолдах
   CDF ≥ 0.80                         ≥ 97% качества полного вектора
   клип min(d, n - 1)
```

1. **Валидация выборки.** Минимум 30 строк и не менее двух классов, иначе `ValueError`. Для сырого текста проверка идёт до загрузки MiniLM и ещё раз после очистки меток; для готовой матрицы `X` — только после `prepare_data`.
2. **Кодирование текста** (`paraphrase-multilingual-MiniLM-L12-v2`, 384-d; только текстовый вход). Вся матрица остаётся в RAM: `batch_size` ограничивает один forward pass, а не срез выборки. Векторы сразу в `float64` — на `float16` SVD в `scikit-learn` теряет стабильность.
3. **Очистка (`prepare_data`).** Пустые метки удаляются, `NaN` и `Inf` зануляются (`np.nan_to_num`). Средним по колонкам пропуски не заполняются, чтобы не утечь в CV. При текстовом входе энкодер проходит все строки, фильтрация меток — уже на матрице эмбеддингов.
4. **Бейзлайн-гейт.** На полном векторе — `RidgeClassifier` или `|Spearman|` косинуса для STS. Прирост vs majority < 0.10 (для STS `|Spearman|` < 0.15) даёт `ValueError`: сигнала нет, сжимать нечего.

### Режимы подбора размерности

**Прогностический режим (по умолчанию).** Вычисляются ровно 5 мета-признаков и передаются в упакованный `RandomForestClassifier`. Лес возвращает вероятности по дискретной сетке `{4, 8, 16, 32, 64, 128, 256}`. Алгоритм берёт наименьший бакет, у которого накопительная вероятность (CDF) достигает ≥ 0.80, после чего применяет клип по рангу матрицы: `min(d, n - 1)`. Это консервативная эвристика порядка величины, исключающая длительный перебор PCA.

**Эмпирический режим (`--empirical` или fallback при отсутствии `.skops`).** Запускает кросс-валидационный перебор сетки PCA. PCA обучается строго на train-фолдах. Алгоритм находит первую размерность, на которой линейная модель удерживает ≥ 97% качества исходного полного вектора. Режим гарантирует точность, но требует ощутимых вычислений из-за многократных прогонов CV.

Метод `DatasetProfiler.fit_transform(texts, labels)` реализует короткий путь: получает эмбеддинги, определяет размерность (через мета-модель или fallback на PCA-95, минуя empirical-сетку) и возвращает сжатую матрицу `PCA(n_components=d).fit_transform(X)`.

## Модули в составе `src/dataset_complexity_profiler/`

Оркестрацией управляет `profiler.py`, вызывая специализированные модули по мере необходимости:

| Файл                   | Назначение                                                                                 |
| :--------------------- | :----------------------------------------------------------------------------------------- |
| `profiler.py`          | Фасад `DatasetProfiler`: точка входа API, CLI-маршруты, стратегия адаптации (`recommend_adaptation`) |
| `cli.py`               | Консольный интерфейс (`dcp analyze --csv` / `--hf`).                                       |
| `features.py`          | Очистка матрицы (`prepare_data`) и расчёт 5 мета-признаков.                                |
| `predict.py`           | Инференс через `skops`, вычисление CDF, клип бакета по рангу выборки.                      |
| `empirical.py`         | Точный подбор размерности полным перебором PCA в кросс-валидации.                          |
| `probes.py`            | Линейные модели: accuracy для `RidgeClassifier` и \|Spearman\| косинусной близости для STS. |
| `id_estimators.py`     | Оценка внутренней размерности: TwoNN и PCA-95 (с ограничением выборки до 2000 строк).      |
| `defaults.py`          | Глобальные константы: сетка размерностей, пороги гейта, имя базового энкодера.             |
| `meta_artifact.py`     | Формат упаковки и валидация мета-артефакта `.skops`.                                       |
| `complexity_report.py` | Диагностический отчёт о геометрии данных; предупреждение при расхождении PCA-95 и TwoNN.   |
| `meta_model.skops`     | Предобученный ансамбль `RandomForestClassifier`.                                           |

### Схема 5 мета-признаков

Порядок колонок строго зафиксирован (иначе сплиты дерева решений будут считывать не те признаки):

1. `class_count` — для классификации это число классов, для STS — число квартильных корзин непрерывного скора;
2. `baseline_quality` — качество линейной модели на полном 384-мерном векторе;
3. `mean_centroid_cosine_distance` — среднее косинусное расстояние между центроидами классов;
4. `intrinsic_dim_twonn` — внутренняя размерность по методу TwoNN (при `n < 5` безопасно возвращает `0.0`);
5. `intrinsic_dim_pca_95` — число компонент PCA, покрывающих 95% дисперсии.

Значения `NaN` в векторе признаков заменяются на `0.0`. Библиотека `PyMFE` в runtime не импортируется, хотя её признаки использовались на этапе оффлайн-исследований.

Артефакт мета-модели сохранён через `skops` (без использования небезопасного `pickle`). Внутри упакован словарь `dict v2`: классификатор `RandomForestClassifier`, имена признаков и версия `scikit-learn` (1.6.1). В зависимостях зафиксировано `scikit-learn>=1.6.1`. Запуск на другой минорной версии ветки 1.x выдаст информационный warning, но не приведёт к сбою.

## Как обучалась мета-модель

Обучающая выборка формируется объединением двух CSV-таблиц с разной структурой, поэтому прямое слияние «в лоб» недопустимо:

1. `research/feature_selection.csv` (~240 строк): содержит расширенный набор признаков `PyMFE` и срезы датасетов с суффиксами `[size=...]`. Использовался для отбора ключевой пятёрки признаков и проведения абляционных тестов.
2. `research/training_extra.csv` (58 корпусов): дополнительные датасеты с Hugging Face, размеченные скриптом `collect_training_extra.py` (одна строка на источник, метка получена через empirical-поиск). Содержит только финальную пятёрку признаков и колонки гейта. В абляционных тестах файл не использовался, чтобы пропуски в колонках `PyMFE` не искажали оценку информативности признаков.

Финальный лес обучается на объединении обеих таблиц после фильтрации бейзлайн-гейтом (итого 254 датасета из 115 уникальных источников).

- Валидация: `GroupKFold` по имени источника без суффикса `[variant]`, что исключает утечки между вариантами одного датасета.
- Таргет: дискретный бакет `pd.cut` по сетке `DIM_BUCKET_BINS` (интервалы закрыты справа: эмпирическое значение 5 или 6 относится к бакету 8, а не 4, обеспечивая консервативный запас ёмкости).

Команда для воспроизведения файла `meta_model.skops`:

```bash
python research/train_meta_model.py \
  --selection-csv research/feature_selection.csv \
  --train-extra-csv research/training_extra.csv
```

Без второго CSV-файла обучение пройдёт только на `selection.csv` — получится локальный эксперимент, а не финальная поставляемая модель. Если флаг `--train-extra-csv` передан, но файл на диске отсутствует, скрипт прерывается с ошибкой (тихий пропуск данных запрещён).

Оба CSV-файла зафиксированы в git для воспроизводимости. В `.gitignore` вынесены кэши, виртуальные окружения `.venv`, черновики и локальные логи сборщика.

## Зависимости, упаковка и CI

Зависимости изолированы в `pyproject.toml`:

- **Core** (минимальное окружение): `numpy`, `pandas`, `scipy`, `joblib`, `skops`, `scikit-learn` — этого достаточно для анализа готовых матриц `X`.
- **Extra `[text]`:** `sentence-transformers` и `datasets` (библиотека `torch` устанавливается транзитивно).
- **Для разработки (`[dev]`):** `pytest`, `ruff`, `build`, `twine`.

Состав пакетов поставки:

- Wheel (`.whl`): pure-Python код библиотеки (без C-расширений), артефакт `meta_model.skops`, маркер типизации `py.typed` и исполняемая консольная команда `dcp`.
- Исходный архив (`sdist`): дополнительно включает директорию с тестами `tests/`.
- Директории `research/` и `docs/` в pip-пакет не включаются: переобучение мета-модели возможно только из клонированного git-репозитория.

CI проверяет сборку на версиях Python 3.9, 3.12 и 3.13:

1. Линтинг и статический анализ (`ruff`).
2. Прогон тестов (`pytest`).
3. Сборка pure-Python дистрибутива wheel.
4. Чистая установка собранного `.whl` без флага `--editable` в изолированное виртуальное окружение.
5. Запуск `dcp --help` из временной директории `/tmp` — это гарантирует, что артефакт `meta_model.skops` корректно включён в состав wheel и успешно загружается вне рабочего репозитория.
