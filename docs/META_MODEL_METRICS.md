# Метрики качества мета-модели

Поставляемая модель: `RandomForestClassifier` (`n_estimators=100`, `class_weight='balanced'`, `n_jobs=1`). Гиперпараметры **не подбирались**: при выборке из 254 датасетов, пяти признаках и семи классах оставлены базовые параметры `scikit-learn` (100 деревьев) со взвешиванием классов для компенсации дисбаланса.

Непрерывный результат эмпирического поиска (`recommended_dim`) квантуется через `pd.cut` по границам корзин `DIM_BUCKET_BINS = (0, 4, 8, 16, 32, 64, 128, 256, 100000)` из `src/dataset_complexity_profiler/defaults.py` (интервалы закрыты справа, `right=True`).

Применяется **консервативное округление вверх**: эмпирическая размерность 5 или 6 относится к бакету 8, а не 4, чтобы модель не сжимала векторы сильнее, чем выдержал зонд. Размерности выше 256 попадают в бакет 256 (бакета 384 в сетке нет).

| Бакет | Полуинтервал | Частота (N=254) | Доля выборки |
|:---:|:---:|:---:|:---:|
| **4** | (0, 4] | 82 | 32.3% |
| **8** | (4, 8] | 41 | 16.1% |
| **16** | (8, 16] | 30 | 11.8% |
| **32** | (16, 32] | 18 | 7.1% |
| **64** | (32, 64] | 44 | 17.3% |
| **128** | (64, 128] | 21 | 8.3% |
| **256** | (128, 100000] | 18 | 7.1% |

## Метрики и бейзлайны

Поскольку задача порядковая (ошибка `16→32` дешевле, чем `16→256`), качество оценивается по двум критериям:

- **Accuracy (точное попадание):** совпадение предсказанного бакета с истинным. Базовое решение (majority) — константный бакет 4 (частота 82/254, Accuracy **0.3228**).
- **Adjacent Accuracy (соседний бакет):** отклонение не больше одного шага сетки (±1 бакет). Сетка логарифмическая (шаг ×2), поэтому допуск ±1 шаг задаёт окно **`[d/2, 2d]`** (четырёхкратный диапазон).
  - Метрика симметрична, но цена ошибки на практике асимметрична: 4 вместо 8 снижает качество зонда, 8 вместо 4 расходует больше памяти.
  - Тривиальный оптимум — константа «всегда 8», покрывающая смежные бакеты 4, 8 и 16 (Adjacent Accuracy **0.6457**).

Критерий Джини в `RandomForestClassifier` трактует бакеты как номинальные. Поставляемая модель намеренно оставлена чистым `RandomForestClassifier` без нестандартных обёрток порядковой регрессии. Поэтому главная отчётная метрика — **Adjacent Accuracy** на `GroupKFold`: она сглаживает дискретность сетки и устойчива на тестовых фолдах (на объединённой выборке — около 23 групп на фолд, на таблице отбора — около 11). Порядковая регрессия Франка–Холла (Frank–Hall) — отдельный оффлайн-эксперимент, в артефакт не входит.

Итоговые результаты (OOF, 5-fold `GroupKFold`):

- **Accuracy:** **0.4252** (против 0.3228 у majority).
- **Adjacent Accuracy:** **0.7874** (против 0.6457 у «всегда 8»).
- Нормализованный прирост к «всегда 8»: `(0.7874 − 0.6457) / (1 − 0.6457) ≈ 0.40`.
- Перестановочный тест (20 прогонов с перемешанными метками): Accuracy `0.167 ± 0.021`, Adjacent `0.436 ± 0.040` — модель извлекает сигнал, а не подстраивается под шум.

## Верхняя граница задачи (шум разметки)

В `feature_selection.csv` на один источник часто приходится 3–4 независимых подвыборки разного размера. На 338 парах таких срезов эмпирический поиск размерности согласуется сам с собой:

- точный бакет: **0.604**
- соседний бакет (±1): **0.870**

Это потолок воспроизводимости для любой модели на данной разметке. Результаты мета-модели 0.425 / 0.787 — около 70% и 90% от этого потолка. Погрешность идёт от стохастики эмпирических меток (`build_quality_curve` берёт первую размерность выше `0.97 ×` качества полного вектора на кривой с бегущим максимумом; один удачный фолд CV фиксирует заниженный ответ), а не от слабости классификатора.

Внутри источника `recommended_dim` коррелирует с `sample_count` (медиана Spearman ≈ 0.63). `sample_count` в пятёрку признаков не входит: иначе модель заучила бы объём подвыборки вместо геометрии.

## Сравнение наборов признаков

Тот же `GroupKFold` OOF, 254 датасета / 115 групп:

| Набор признаков | Accuracy | Adjacent Accuracy |
|:---|:---:|:---:|
| **Все 5** | **0.4252** | **0.7874** |
| Только `class_count` | 0.3701 | 0.7559 |
| Четыре геометрических, без `class_count` | 0.3150 | 0.6772 |
| Константа «всегда 8» | 0.1614 | 0.6457 |

Без `class_count` геометрия почти неотличима от константы (0.677 против 0.646).

Ранговая корреляция Спирмена с целевым бакетом: `class_count` **+0.558**, `baseline_quality` **+0.242**, `intrinsic_dim_pca_95` **+0.040**, `intrinsic_dim_twonn` **−0.474**. TwoNN здесь скорее отражает вырожденность или размер выборки, чем внутреннюю размерность.

На многоклассовых выборках (Banking77, CLINC, TREC, MTOP) модель опирается преимущественно на `class_count`. Эти корпуса уже входят в таблицу отбора и не годятся как отдельный holdout.

## Структура обучающих выборок и фильтрация

Обучающая выборка — объединение двух CSV-файлов:

- [`research/feature_selection.csv`](../research/feature_selection.csv) — **240** строк / **64** источника, содержит колонки признаков `PyMFE`. Отбор пятёрки признаков — только здесь ([`research/feature_selection.ipynb`](../research/feature_selection.ipynb)).
- [`research/training_extra.csv`](../research/training_extra.csv) — **58** источников, одна строка на источник, только пятёрка признаков и колонки гейта. Дубликат `Tweet sentiment German` удалён (совпал с `German sentiment`). В абляционные тесты файл не входит: пропуски колонок `PyMFE` исказили бы сравнение семейств признаков.

Численный порог (`linear_sep_value` против `linear_sep_threshold`) отбрасывает **44** строки / **18** источников таблицы отбора (прирост точности зонда над majority < 0.10 или `|Spearman|` < 0.15) **до** кросс-валидации — то есть фильтрует и тестовые фолды. Дополнение уже прошло порог на этапе сбора. Среда выполнения использует тот же критерий: `analyze_and_adapt` / `predict_embedding_dim` / `estimate_intrinsic_dim` выбрасывают `ValueError`. Метрики OOF относятся к отфильтрованному распределению.

После порога: **196 + 58 = 254** датасета / **57 + 58 = 115** групп. Оба набора объединяются до начала кросс-валидации и участвуют в обучении поставляемой модели. Отсутствие колонок порога фильтрации прерывает обучение с ошибкой.

## Валидация: GroupKFold и OOF

Единица группировки — источник, не строка. `GroupKFold(n_splits=5)` по имени без суффикса `[variant]`, в нижнем регистре. Построчных утечек нет. Корпусная утечка остаётся: близкие корпуса под разными именами (`Amazon Reviews Classification EN` / `Amazon Reviews Multi EN`, `SST-2` / `SST-5`, семейства STS / TweetEval / LexGLUE) могут попадать в разные фолды.

OOF того же `RandomForestClassifier`:

| Данные | Строк | Групп | RF Accuracy | Adjacent Accuracy | Majority Accuracy |
|:---|:---:|:---:|:---:|:---:|:---:|
| `feature_selection.csv` после гейта | 196 | 57 | **0.36** | **0.79** | 0.32 |
| Объединённая выборка (`selection` + `extra`) | 254 | 115 | **0.43** | **0.79** (среднее по фолдам ≈ 0.76) | 0.32 |

- Accuracy по фолдам: 0.53, 0.55, 0.31, 0.51, 0.26 (среднее ≈ 0.43).
- Adjacent Accuracy по фолдам: 0.78, 0.78, 0.75, 0.82, 0.68 (среднее ≈ 0.76).
- Совокупная OOF Adjacent Accuracy = **0.7874** (расхождение со средним по фолдам объясняется разным размером тестовых фолдов).

## Воспроизведение артефакта

`src/dataset_complexity_profiler/meta_model.skops` — `RandomForestClassifier`, пять признаков, формат v2, `scikit-learn` **1.6.1**, сериализация **skops** (не `pickle`). Зависимость: `scikit-learn>=1.6.1` (как в `pyproject.toml`); на других минорных версиях ветки 1.x генерируется предупреждение (warning), не блокирующее загрузку. `predict_embedding_dim` ограничивает прогноз рангом матрицы; при `n < 30` все публичные входы, включая `estimate_intrinsic_dim` и `analyze_text_dataset`, выбрасывают `ValueError` (проверка выполняется до кодирования).

```bash
python research/train_meta_model.py \
  --selection-csv research/feature_selection.csv \
  --train-extra-csv research/training_extra.csv \
  --cv-folds 5 \
  --task-families single,pair,sts
```
