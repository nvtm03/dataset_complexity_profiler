## Аннотация

В прикладном NLP для задач классификации и семантического анализа стандартом де-факто стало использование предобученных эмбеддингов языковых моделей (например, `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` формирует 384-мерные плотные векторные представления). На большинстве прикладных корпусов линейному зонду достаточно нескольких десятков главных компонент. Удержание полноразмерного вектора влечёт избыточный расход оперативной памяти и замедляет обучение downstream-классификатора, тогда как эвристическое сжатие вслепую создаёт риск потери качества.

Точный подбор размерности требует полного перебора PCA с линейным зондом на кросс-валидации. Этот подход надёжен, но вычислительно дорог: на каждом новом датасете требуются многократные прогоны SVD и обучения зонда. Возникает потребность в легковесном инструменте, способном **до запуска тяжёлых вычислений** оценить порядок необходимой размерности и выявить задачи, где сжатие бессмысленно из-за отсутствия сигнала.

**Dataset Complexity Profiler** — специализированная open-source Python-библиотека под эту задачу.

- **Входные данные:** размеченные текстовые выборки либо предварительно вычисленные матрицы эмбеддингов.
- **Выходные данные:** рекомендуемый дискретный бакет размерности PCA из сетки `{4, 8, 16, 32, 64, 128, 256}` и эвристическая стратегия адаптации энкодера (`linear_head`, `mlp_head`, `adapters`, `full_finetune`).

По умолчанию библиотека рассчитывает 5 геометрических мета-признаков и опрашивает предобученный `RandomForestClassifier`. Для задач, где нужна опора на зонд, доступен эмпирический режим: полный перебор PCA на train-фолдах. Если базовый зонд не превосходит случайное угадывание, библиотека прерывает выполнение с `ValueError` и не сжимает данные без сигнала.

Пакет опубликован на **PyPI (версия 0.3.0)**, снабжён модульными тестами и CI. Ядро не требует PyTorch при работе с готовыми эмбеддингами. Код обучения мета-модели живёт в `research/` и в wheel не входит.

## Проблематика и контекст

### Целевая аудитория

Инженеры машинного обучения, NLP-исследователи и разработчики, оптимизирующие пайплайны обработки текстов. В контексте учебной практики проект решает методическую инженерную задачу: создание законченной, автономной и воспроизводимой библиотеки — от сбора мета-датасетов до публикации в PyPI.

### Практическая проблема

Широкое применение трансформеров порождает дилемму избыточной размерности:

1. **Инерционный подход:** оставлять полные 384 измерения. Это безопасно для качества, но неэффективно по памяти при кэшировании признаков, векторном поиске и обучении ансамблей.
2. **Наивное сжатие:** фиксация произвольной размерности (например, `d = 32`). Это не даёт гарантий сохранения качества на конкретном распределении данных.
3. **Честный перебор PCA:** запуск сетки с кросс-валидацией занимает минуты на каждый корпус, что нерационально при потоковом анализе сотен датасетов.

Dataset Complexity Profiler даёт быструю предварительную оценку ёмкости признакового пространства: порядок размерности до полного перебора и отказ, если сжимать нечего.

## Постановка задачи

В рамках проекта требовалось спроектировать и реализовать инструмент, выполняющий до этапа основного обучения:

1. **Экспресс-профилирование:** расчёт 5 интерпретируемых мета-признаков выборки в пространстве эмбеддингов (`class_count`, `baseline_quality`, `mean_centroid_cosine_distance`, `intrinsic_dim_twonn`, `intrinsic_dim_pca_95`).
2. **Прогнозирование размерности:** предсказание консервативного бакета PCA с помощью мета-модели либо точный эмпирический подбор в режиме `--empirical`.
3. **Валидационный гейт (fast-fail):** автоматический отказ от сжатия с выбросом `ValueError`, если линейная разделимость выборки не превышает тривиальный dummy-бейзлайн.
4. **Рекомендация стратегии адаптации:** эвристическое правило по дальнейшей работе с энкодером на основе геометрии классов (`linear_head`, `mlp_head`, `adapters`, `full_finetune`).
5. **Инженерная поставка:** pip-пакет с консольным интерфейсом (`dcp`), минимальными зависимостями ядра и воспроизводимым пайплайном переобучения.

**Границы применимости:** мета-модель обучалась и предназначена исключительно для плотных векторных представлений трансформеров (`SentenceTransformer`). Инструмент не тестировался и не предназначен для разнородных табличных данных со смешанными типами колонок (OpenML).

## Описание технического решения

Архитектура проекта разделена на два независимых слоя:

```text
┌─────────────────────────────────────────────────────────────┐
│                       RESEARCH-СЛОЙ                         │
│  254 датасета (Hugging Face) ──► Расчёт признаков ──► Гейт  │
│  Валидация GroupKFold(5) ────► Обучение RF ──► meta_model   │
└──────────────────────────────┬──────────────────────────────┘
                               │ Сериализация в .skops
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                       RUNTIME-СЛОЙ                          │
│  CLI (dcp) / Python API (DatasetProfiler)                   │
│  текст: n < 30 → MiniLM → prepare     матрица X → prepare   │
│  Бейзлайн-гейт ──► 5 мета-признаков ──► CDF ≥ 0.80 / empirical │
└─────────────────────────────────────────────────────────────┘
```

Подробности кода — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Сравнение с литературой — [docs/RELATED_WORK.md](docs/RELATED_WORK.md).

### 1. Runtime-слой (поставляемый пакет)

- **Точки входа:** класс `DatasetProfiler` и консольная утилита `dcp analyze`.
- **Контроль вычислений:** проверка выборки (`n ≥ 30`, не менее двух классов) для сырого текста срабатывает до загрузки весов MiniLM; векторы сразу приводятся к `float64` для численной стабильности SVD в `scikit-learn`.
- **Защита от data leakage:** пропуски в матрице зануляются (`np.nan_to_num`), заполнение средним по колонкам исключено.
- **Безопасная сериализация:** артефакт мета-модели сохранён через `skops` (не `pickle`).
- **Модульность зависимостей:** базовый пакет зависит только от `numpy`, `pandas`, `scipy`, `joblib`, `skops` и `scikit-learn`. `torch`, `sentence-transformers` и `datasets` изолированы в extra `[text]`.
- Порог «зонд ≈ dummy» один и тот же при сборе меток и в runtime.

### 2. Research-слой (пайплайн исследований и обучения)

- **Обучающая выборка:** объединение бенчмарка отбора признаков с `PyMFE` (240 строк) и дополнительного пула датасетов (58 строк). После отсечения неразделимых задач бейзлайн-гейтом итоговый датасет включает 254 выборки из 115 независимых групп источников.
- **Методология валидации:** `GroupKFold(n_splits=5)` по источнику данных, без построчных утечек между подвыборками.
- **Абляционные тесты:** компактный вектор из 5 геометрических признаков даёт более высокую обобщающую способность, чем набор из 30 статистик `PyMFE`. `PyMFE` из runtime-зависимостей исключён.

Постановка «признаки задачи → выбор действия» опирается на схему выбора алгоритма (Rice / Kerschke) и меры сложности классификации (Lorena). Действие — бакет PCA, а не выбор классификатора `scikit-learn`.

## Полученные результаты

Цифры, ablation и оговорки — [docs/META_MODEL_METRICS.md](docs/META_MODEL_METRICS.md).

### Метрики мета-модели (Out-of-Fold, 5-fold `GroupKFold`)

- **Accuracy** (точное попадание в бакет): **0.4252** (при мажоритарном бейзлайне 0.3228).
- **Adjacent Accuracy** (попадание в диапазон `[d/2, 2d]`): **0.7874** (против 0.6457 у тривиального бейзлайна «всегда 8»).
- **Нормализованный прирост:** `(0.7874 − 0.6457) / (1 − 0.6457) ≈ 0.40` над «всегда 8».
- **Перестановочный тест** (20 прогонов): при перемешивании меток Adjacent Accuracy падает до `0.436 ± 0.040` — модель извлекает геометрический сигнал, а не подстраивается под шум.

### Физический потолок задачи (noise ceiling)

На 338 парах повторных подвыборок одного корпуса процедура эмпирического поиска размерности согласуется сама с собой на **0.60** (точный бакет) и **0.87** (соседний бакет). Мета-модель достигает около 70% и 90% от этого потолка воспроизводимости разметки. Ограничение идёт от стохастики эмпирических меток, а не от слабости классификатора.

### Практическая эффективность

На типовых текстовых задачах, прошедших бейзлайн-гейт, модель рекомендует сжатие до 16–32 компонент вместо исходных 384 при сохранении ≥ 97% качества baseline-зонда. Задачи, где зонд не превосходит dummy, библиотека отсекает и размерность не выдаёт.

### Состояние репозитория и релиз

- Пакет опубликован на PyPI: `pip install dataset-complexity-profiler` (версия **0.3.0**).
- Тестовый набор на `pytest` (модульные тесты, сериализация, runtime-гейты).
- CI (GitHub Actions) проверяет сборку и чистую установку wheel-пакета на Python 3.9, 3.12 и 3.13.

## Методологические границы и дальнейшее развитие

Проект выполнен в формате прикладного R&D и разработки открытого ПО. Валидация строится на статистике, воспроизводимости и потолке шума разметки, а не на корпоративных отчётах о внедрении.

Внедрение в распределённые оркестраторы (Airflow, Kubeflow) и интеграция в специфичные корпоративные контуры вынесены за рамки базового пакета, чтобы сохранить легковесность и независимость.

### Векторы дальнейшего развития открытого инструмента

1. **Расширение пула энкодеров:** адаптация и валидация мета-модели на эмбеддингах моделей большего масштаба (семейства BGE, E5, Nomic).
2. **Доменно-специфичное переобучение:** скрипт `research/train_meta_model.py` для калибровки профилировщика под узкие домены (медицинские или юридические тексты).
3. **Расширение сетки предиктора:** эксперименты с непрерывной квантильной регрессией для более гибкого предсказания границ сжатия.
